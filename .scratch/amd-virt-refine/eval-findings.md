# 评测暴露的技能缺陷（待修，评分完成后统一处理）

来自**作答阶段**的路由观察，与评分无关——这些是 agent 在用技能时真实撞到的。

## R1 · `00-quickref.md` §0.2 在 Windows 症状上过薄

诊断题 20 道里有 **6 道在 §0.2 没有对应行**：HVCI 驱动被拒、Kernel DMA Protection、嵌套 Hyper-V、GPU 直通、VBS 状态检查、AVIC 默认值。

主路由表把这 6 道全部解决了，其中 4 道还靠 `16-windows-platform.md` §16.1.3 自己的症状表定位到了准确小节。**但 §0.2 才是症状入口**，SKILL.md 第 1 步就写着"如果问题是症状而非主题，用 §0.2"。它漏掉 Windows 症状，等于把最常见的一类问题推回给主路由表。

修法：给 §0.2 补 Windows 症状行，并考虑把 §16.1.3 的症状表提升/交叉引用。

## R2 · §0.2 没有"缓解措施禁用了 SEV-ES"这一行

`diag-sev-es-disabled-on-snp-host` 在 §0.2 里最接近的一行是"SEV guest fails to launch / firmware returns an error" → `12-sev.md` §12.8，**owner 错了**。真正的 owner 是 `17-security.md` §17.1（AMD-SB-3023 / CVE-2025-48514）。

作答 agent 是靠 `errata.md` E17 找对的——因为 SKILL.md 第 3 步强制先查 errata。**这说明 errata 的"动笔前必查"规则救了一次错误路由**，但不该指望它。

同章内偏移。章对节错，代价小但应修准。

## R4 · SKILL.md 路由表的小节锚点是"章入口"而非 owner 小节

查询题 24 道全部路由到正确章节，但**七处小节锚点指向的不是拥有该事实的小节**：

| 主题 | 路由表写 | 实际 owner |
|---|---|---|
| VMCB clean bits | `02-vmcb.md` §2.2 | §2.5 |
| 偏移 60h 虚拟中断控制字 | `07` §7.2 | §7.1 |
| MSRPM | `03` §3.1 | §3.4 |
| `TLB_CONTROL` | `06` §6.5 | §6.8 |
| IRTE 格式 | `10` §10.4 | §10.1–§10.3 |
| IOMMU 控制寄存器 | `08` §8.6 | §8.3 |
| SEV 状态码 | `12` §12.6 | §12.8.2 |

**没有造成错误答案**：每次 `00-quickref.md` §0.3「表格在哪一章」都给出了准确小节，而读者此时已经打开了那个文件。但锚点应当准确——写路由表时我用的是"这一章从哪读起"的直觉，而题目问的是"这个值在哪"。

两者都有道理，所以修法不是简单替换：**入口锚点对"我要了解这一章"有用，owner 锚点对"我要查这个值"有用**。路由表面向的是后者，应改为 owner 小节。
