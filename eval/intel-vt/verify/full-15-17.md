## 3. The two questions asked specifically

### 3.1 §17.1's governing claim — **it holds, with one sentence removed**

The claim under test: *enabling VBS or any Hyper-V-backed feature makes the Windows kernel a VTL0
guest and gives Hyper-V ownership of VMX root operation.*

| Element | Verdict | Evidence |
|---|---|---|
| One owner of VMX root operation per logical processor | CONFIRMED | SDM 3C Ch.26; `[SDM 3C Ch.26]` is the right anchor |
| The management Windows is a *partition*, not the hypervisor | CONFIRMED | scheduler-types page: "The root partition **is itself a VM partition**, although it has unique properties and greater privileges than guest VMs" |
| The hypervisor holds the hardware exclusively | CONFIRMED | TLFS VSM: the hypervisor "has exclusive control of key system hardware resources such as memory access permission controls in the CPU MMU and IOMMU **early in system initialization**"; KB 3204980: "only one software component at a time can use this hardware. Virtualization applications can't share the hardware" |
| Normal Windows runs in VTL0 | CONFIRMED | TLFS: "When a partition starts or resets, it begins running in VTL0." IUM page: "the code running in the traditional model executes in VTL0 and it cannot access the higher privileged VTL1, where the Secure Kernel and Isolated User Mode (IUM) execute code" |
| Enabling VBS starts the hypervisor with no VM defined | CONFIRMED | KB 3204980 names memory integrity and Credential Guard as Hyper-V-dependent; `oem-vbs` requires the Windows hypervisor |
| "it launches **before the Windows kernel**" | **UNSUPPORTED — removed** | No current Microsoft document states the boot order. The hvboot.sys → hvix64.exe sequence appears only in community and archived TechNet material. Replaced by the TLFS's "early in system initialization", which is documented |
| The phrase "VMX root operation" | **Not Microsoft's** | Zero hits for `vmx root`, `root operation`, `VMX operation` or `VMXON` across Hyper-V Architecture, all TLFS pages, VSM, the WHP docs, the scheduler page and KB 3204980. It is Intel vocabulary layered onto Microsoft's statement, and §17.1 now says so |

**Conclusion: the governing claim stands.** Every consequence the chapter hangs off it is
documented. Two things were wrong about *how* it was stated, and both are fixed: the boot-order
sentence had no source, and the chapter presented Intel's terminology as if Microsoft used it.
