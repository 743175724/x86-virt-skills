## The fourteen `WRONG` findings in one place

1. `01` §1.6 **IA32_VMX_BASIC bit 56** — it reports that VM entry can deliver a hardware exception with or without an error code regardless of vector, not zero-length software-event injection (that is IA32_VMX_MISC bit 30).
2. `01` §1.6 **bits 53:50** — the reported memory type covers the VMCS, the structures a VMCS references and the MSEG header; the VMXON region is not in the SDM's list.
3. `01` §1.7 **VMXON-region memory type** — the SDM's write-back requirement is stated for the VMCS region (§27.2), and UC degrades *software* accesses (A.1 fn 3), not "the performance of VMX transitions".
4. `01` §1.8 **VMXOFF** — A20M is re-enabled only when the logical processor is outside SMX operation.
5. `01` §1.9 **INIT** — blocked in VMX *root* operation only; in non-root it causes VM exits.
6. `01` §1.10.1 — SMSW is not intercepted (it reads through the CR0 read shadow) and PUSHF/POPF have no interception control; only SGDT/SIDT/SLDT/STR are the unprivileged descriptor-table reads.
7. `03` §3.2 **VMFUNC** — EAX > 63 causes #UD, not a VM-exit.
8. `03` §3.3 **descriptor-table instructions** — LGDT/LIDT/LLDT/LTR were always privileged; only the four store forms leaked at CPL 3.
9. `03` §3.5 **unconditional I/O exiting** — it applies only when use-I/O-bitmaps is 0.
10. `03` §3.5.1 **I/O RCX/RSI/RDI/RIP** — used only for VM exits caused by SMIs arriving immediately after an I/O instruction retires, never on an ordinary I/O VM-exit.
11. `03` §3.8 **CR3-target count** — VM entry fails when the count is greater than 4; IA32_VMX_MISC bits 24:16 are informational (0–256).
12. `03` §3.11 **NMI-window** — the exit also requires no blocking by MOV SS and none by STI.
13. `03` §3.13 **monitor trap flag** — no MTF exit occurs in the shutdown or wait-for-SIPI states; the HLT activity state is the real case.
14. `03` §3.4.2 **IDT-vectoring field names** — rev 092 calls them the original-event identification and original-event error code fields.

Items 1–6 are the six in `01` (claims 01-31, 01-26, 01-40, 01-47, 01-48, 01-55); items 7–14
are the eight in `03` (claims 03-10, 03-13, 03-34, 03-40, 03-50, 03-61, 03-70, 03-32). Every

## Note on the §1.10 history claims

Six claims in `01` §1.10 (01-53, 01-54, 01-56, 01-57, 01-58, 01-59) carry `[SDM 3C Ch.26]`
alongside a Tier-2 or Tier-3 citation. Chapter 26 contains nothing about Popek and Goldberg,
Robin and Irvine, the Vanderpool announcement, the IEEE Computer paper, the Pentium 4 ship
date or the Intel Technology Journal article. Those anchors therefore attest nothing and are
`UNSUPPORTED` on the evidence.

They were **not** removed, and no substitute section number was invented for them. The reason
is that `CONVENTIONS.md` §2–§3 and lint rule 4 in `tools/lint.mjs` both require a Tier-1
anchor on every claim line in chapters 01–14, and the linter's only escape hatch
(`offSpec.subjects`) covers Windows and CVE subjects, not historical ones. Dropping the anchor
would fail the lint; inventing a finer section number would be exactly the defect this pass
exists to find. Instead, §1.13 item 4 of the chapter now states in the file itself that these
chapter anchors attest nothing and that the Tier-2 citation is the real source. The clean fix
is a linter change — an `offSpec`-style exemption for dated/historical claims, or a
`[no-spec]` anchor token — which is outside the scope of this verification pass.
