## Verdict key

- **C** — CONFIRMED: the PDF says this, at the cited section.
- **W** — WRONG: the PDF contradicts the claim (a false value, or a false completeness assertion).
- **U** — UNSUPPORTED: the cited section resolves but does not contain the claim.
- **?** — UNVERIFIABLE.

Verdicts describe the text **as found**. The "Fix" column records what was changed. Line numbers are
post-fix, so the table can be used as a map of the current files.

## 2. Findings — every WRONG, with the correction

### W1 — `02-vmcs.md:140` — "Two further 16-bit guest-state fields"
Table B-2 lists **three** fields after the eight selectors: `0x0810` guest interrupt status,
`0x0812` PML index and **`0x0814` guest UINV** (index `000001010B`).
**Fixed:** "Three further … and `0x0814` guest UINV."

### W2 — `02-vmcs.md:155` — "Two further 64-bit guest-state fields follow the PDPTEs"
Table B-6 continues for **nine** more entries past `0x2814`: `0x2816` IA32_LBR_CTL, `0x2818`
IA32_PKRS, `0x281A`–`0x2828` the eight FRED MSRs, `0x282E` IA32_SPEC_CTRL, `0x2830` guest deadline.
**Fixed:** "The 64-bit guest-state list continues past the PDPTEs: …" with the full run.

### W3 — `02-vmcs.md:174` — "The remaining natural-width guest-state fields"
Table B-14 does not stop at `0x6826`. It continues `0x6828` guest IA32_S_CET (`000010100B`),
`0x682A` guest SSP, `0x682C` guest IA32_INTERRUPT_SSP_TABLE_ADDR.
**Fixed:** the three CET fields appended. (`0x6C18`/`0x6C1A`/`0x6C1C`, the host counterparts of
Table B-15, were added to line 175 at the same time — that claim asserted no completeness, so it is
counted C, not W.)

### W4 — `02-vmcs.md:195` — "The guest-state register fields **comprise** …"
§27.4.1's list also contains IA32_LBR_CTL, IA32_S_CET, IA32_INTERRUPT_SSP_TABLE_ADDR, IA32_PKRS, the
eight FRED MSRs and IA32_SPEC_CTRL, plus two registers the claim omits entirely: **SSP** and
**SMBASE**. SMBASE is doubly conspicuous because the chapter's own §2.5.4 gives its encoding
(`0x4828`).
**Fixed:** full list, with the support conditions stated once.

### W5 — `02-vmcs.md:348` — VM-entry control bit 9 does not load IA32_EFER.LME
> "…pokes a reserved bit that must be 1, whose value is loaded into IA32_EFER.LMA and LME on VM entry."

Table 27-17 bit 9 (IA-32e mode guest): *"Its value is loaded into IA32_EFER.LMA as part of VM
entry."* **LMA only.** CS.L and IA32_EFER.**LME** are loaded by the *VM-exit* control bit 9
(host address-space size), Table 27-14: *"Its value is loaded into CS.L, IA32_EFER.LME, and
IA32_EFER.LMA on every VM exit."* The trailing relative clause also dangled off "a reserved bit."
**Fixed:** clause removed from :348; a new claim at :349 states the LMA-only entry rule and contrasts
it with the VM-exit control explicitly.

### W6 — `06-address-translation.md:74` — the ignore-PAT rule is conditional on CR0.CD
§31.3.7.2 makes CR0.CD the outer test: *"If CR0.CD = 0, the effective memory type depends upon the
value of bit 6 … If CR0.CD = 1, the effective memory type is UC."* As written the claim gives an
unconditional rule that is false whenever the guest sets CR0.CD.
**Fixed:** CR0.CD = 0 made the precondition; the CD = 1 ⇒ UC override and "MTRRs have no effect"
added. The mirror-image omission in the EPTP claim at :60 (§31.3.7.1) was closed the same way.

### W7 — `06-address-translation.md:151` — not-present entries: bits **62:3**, not "the remaining bits"
§31.3.2: *"An EPT paging-structure entry is present if any of bits 2:0 is 1 … The processor **ignores
bits 62:3** … (If the 'EPT-violation #VE' VM-execution control is 1, the EPT violation is convertible
to a virtualization exception only if bit 63 is 0.)"* Bit 63 is *not* ignored. A VMM that zeroes an
EPT entry for demand paging while EPT-violation #VE is on reflects the fault into the guest.
**Fixed:** "ignores **bits 62:3** … bit 63 is *not* among the ignored bits."
(`ept-apic-vs-sdm.md` F9 fixed the §6.3.1 table row but not this claim.)

### W8 — `06-address-translation.md:169` — "arbitrary values in the upper bits of a zeroed entry"
Same defect, other end of the chapter. Bit 63 of a not-present entry is load-bearing.
**Fixed:** scoped to bits 62:3, with bits 2:0 and bit 63 called out as exceptions.

### W9 — `06-address-translation.md:351` — bit 61 is not "an EPT leaf entry" bit
Bit 61 (sub-page write permissions) exists **only in Table 31-7**, the EPT PTE that maps a 4-KByte
page. In Table 31-3 (1-GByte leaf) and Table 31-5 (2-MByte leaf) bits **62:61 are "Ignored."**
§31.3.4.1: *"a guest-physical address is eligible for sub-page write permissions only if it is mapped
using a 4-KByte page … (Guest-physical addresses mapped with larger pages are not eligible.)"*
**Fixed:** "defined **only in an EPT PTE that maps a 4-KByte page**." (The §6.3.1 table row already
said this; the claim contradicted its own table.)

### W10 — `06-address-translation.md:373` — SPP eligibility is not a leaf-entry test
§31.3.4.1: *"A guest-physical address is eligible for sub-page write permissions if writes to it
would be disallowed following Section 31.3.3.2: bit 1 (write access) is clear in **any** of the EPT
paging-structure entries used to translate the guest-physical address."* Not only the leaf.
**Fixed:** "in **any** of the EPT paging-structure entries used to translate the guest-physical
address — not only in the leaf," plus the SDM's exclusion of writes disallowed for other reasons.

### W11 — `06-address-translation.md:407` — the #VE conversion list was self-contradictory
The claim announced "**all six** of the following … (the list below is complete)" and then listed
**three** items, two of which are prerequisites rather than conditions, while naming CR0.PE and
event delivery only parenthetically and omitting the shadow-stack, Intel PT and PEBS clauses
entirely. §28.5.8.1 separates two prerequisites (control = 1; bit 63 = 0 in the one deciding entry)
from six conditions: CR0.PE = 1; not in the process of delivering an event; did not cause a shadow
stack to become prematurely busy; not from the Intel PT output process; not from PEBS; and the 32
bits at offset 4 of the #VE information area all 0.
**Fixed:** rewritten as two prerequisites plus a numbered six, verbatim against §28.5.8.1.
(This is the finding `ept-apic-vs-sdm.md` F13 raised; the fix applied from it was incomplete.)

### Tier-1 anchors replaced by `[no-spec]`

`grep -c "shadow paging"` over Vol.3C rev 092 returns **0**. Five measurement claims in `06` carried
`[SDM 3C Ch.31]` as a co-anchor for figures the SDM does not state and, in three cases, for a
comparison the SDM never makes. Four of them are the textbook `[no-spec]` case — a published
measurement that no specification can carry — and now use that escape, keeping the Tier-2 citation
that actually supports them. The fifth keeps a genuine Tier-1 anchor for the architectural half of
its sentence:

| Line | Claim | Now |
|---|---|---|
| `06:34` | shadow paging 29.2% slower than native | `[no-spec]` `[109]` `C:medium` |

`[no-spec]` is the right answer here precisely because the alternative — reaching for a
plausible-looking Ch.31 section to satisfy rule 4 — is what produced the fabricated anchors this

hidden behind a section number that does not discuss their subject.

## 6. Two cross-file notes

- **`02` §2.5.6 and `06` §6.4.1 both carried a "we could not confirm this" hedge that rev 092
  refutes.** Five such hedges existed across the two chapters (secondary VM-exit controls, HLAT
  fields, PASID fields, instruction-timeout control, tertiary bits above 4, later VM-exit controls,
  the misconfiguration conjunctions). All are now stated from the PDF. A hedge is the right default
  under uncertainty, but a hedge that survives a full pass over the source becomes a silent gap.
- **Naming drift is unaddressed and deliberate.** `02` still uses the pre-092 field names
  (VM-entry interruption information, VM-exit interruption information, IDT-vectoring information).
  Every one of these is footnoted in Appendix B as "Older versions of this document called this
  field …", so the names resolve, and `05-vm-exit.md` and the eval both key off them. Changing them
  is a corpus-wide rename, not a fact fix, and is out of scope here.
